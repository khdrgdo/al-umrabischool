# حالة المشروع — نظام إدارة مدرسة العمرابي

## المرحلة الحالية: الأساس (المراحل 0–4 جزئيًا)

### يعمل
- تسجيل الدخول بالبريد وكلمة المرور، مع تأكيد البريد.
- الأدوار: المالك، مدير المدرسة، المشرف (جدول منفصل، مفروضة في قاعدة البيانات عبر RLS).
- أول حساب يُنشأ يصبح المالك تلقائيًا؛ بقية الحسابات بلا صلاحية حتى يمنحها المالك.
- المدرسة، السنوات الدراسية (سنة حالية واحدة فقط)، الصفوف، المسارات، التخصصات، الشعب.
- المواد والمعلمون (إضافة، إيقاف/تفعيل — لا حذف).
- ملف الطالب منفصل عن التسجيل السنوي؛ تسجيل واحد لكل طالب في كل سنة (قيد في القاعدة).
- الرقم المدرسي يولده النظام للطلاب الجدد بصيغة OMR-000001؛ الأرقام القديمة (6 أرقام) باقية كما هي ولا يمكن تعديل أي رقم.
- سجل تدقيق تلقائي لكل إضافة/تعديل على الجداول الأساسية وعلى منح الأدوار.

### الصلاحيات المطبقة
| العملية | المالك | المدير | المشرف |
|---|---|---|---|
| قراءة البيانات | ✔ | ✔ | ✔ |
| إضافة/تعديل | ✔ | ✔ | ✘ |
| منح الأدوار | ✔ | ✘ | ✘ |
| قراءة سجل التدقيق | ✔ | ✔ | ✘ |
| حذف الطلاب/التسجيلات | ✘ (غير مسموح لأحد) | ✘ | ✘ |

### لم يُنفذ بعد
- تغيير حالة الطالب (نقل/انسحاب/تخرج) من الواجهة — الحالات موجودة في القاعدة.
- الترحيل السنوي (يتطلب قواعد النجاح والرسوب).
- الجدول الدراسي، الحضور، الدرجات، المالية، الإعلانات، API ولي الأمر، العمل دون إنترنت.

### لم يُختبر آليًا
- سياسات RLS باختبارات تلقائية (اختُبرت منطقيًا فقط). اختبار وحدة لقاعدة الصلاحيات في `src/test/staff.test.ts`.

## أسئلة مفتوحة (تحتاج قرار الإدارة)
1. **الحضور:** يومي لكل فصل أم لكل حصة؟ (غير محسوم — الوحدة مؤجلة)
2. **المالية:** ضمن النطاق الآن. نحتاج: أنواع الرسوم، مبالغها، الأقساط، الخصومات والمنح، طرق الدفع، سياسة التصحيح.
3. **الدرجات:** توزيع الدرجات، أوزان الاختبارات، طريقة حساب النتيجة، درجة النجاح.
4. **الترحيل:** شروط الترحيل والإعادة.
5. **الجدول:** عدد الحصص وأيام الأسبوع وأوقاتها.
6. **صلاحيات المشرف:** هل يسجل الحضور أو يدخل الدرجات؟

## القرارات المعتمدة
- المسار العلمي للصف الثالث: أحياء/حاسوب/هندسية = **تخصصات داخل المسار**.
- الخلفية: Lovable Cloud (قاعدة بيانات PostgreSQL + مصادقة + سياسات أمان على مستوى الصف).
