## C. التعارضات والفجوات

1. **رمز التفعيل ≠ OTP.** رمز التفعيل الحالي تصدره الإدارة ويُسلَّم يدوياً، صالح 72 ساعة، لإنشاء الحساب أول مرة. OTP الاستعادة يجب أن يطلبه الولي بنفسه ويصل آلياً إلى وسيلة موثقة، قصير العمر (5–10 دقائق)، أحادي الاستخدام. الموجود لا يحقق الثاني. [مؤكد]
2. **تعارض مع APP-2 (القسم 6):** المرجع الملزم ينص أن "إعادة التعيين تبدأ من المدير بعد حضور الولي". قراركم الأحدث استعادة ذاتية بـ OTP. يحتاج قراراً صريحاً بتحديث APP-2. [مؤكد]
3. **صيغة رقم الولي:** APP-2 يشترط معرّف دخول عشوائياً غير متسلسل، ويجعل صيغة مثل `PAR-000125` للعرض فقط. قراركم "رقم داخلي ثابت يولده النظام" متوافق إن كان عشوائياً، ومتعارض إن كان متسلسلاً. [غير محسوم — يحتاج قراركم]
4. **وسيلة الاتصال الموثقة:** FIX-1 يترك سؤالاً مفتوحاً: "هل يملك كل ولي هاتفاً موثقاً؟". لا يوجد حقل `phone_verified_at`. [مؤكد]
5. **أولياء عبر مدارس متعددة:** `guardians.school_id NOT NULL` يربط الولي بمدرسة واحدة، بينما القرار يسمح بأبناء في مراحل ومدارس مختلفة. [مؤكد]
6. **حالة التحقق في الرابط:** لا توجد حالة (pending/verified/revoked) ولا تواريخ؛ `ON DELETE CASCADE` من guardians يخالف قاعدة عدم الحذف. [مؤكد]
7. **تقييد المعدل** داخل الذاكرة فقط، ولا يوجد جدول محاولات (APP-2 يقترحه). [مؤكد]
8. **مزامنة الحالة:** إيقاف الولي في guardians لا يلغي جلسات Auth الحالية تلقائياً. [مرجّح]

**خيارات OTP (لا يوجد مزود مهيأ):**
- (أ) OTP هاتفي عبر مزود SMS يُربط لاحقاً (يحتاج حساب مزود وتكلفة وقراراً) — الأفضل حسب قراركم.
- (ب) OTP عبر بريد حقيقي موثق — ممكن تقنياً، لكن ليس كل ولي يملك بريداً، والبريد الحالي اصطناعي.
- (ج) بديل مؤقت: استعادة إدارية حضورية (الموجود في APP-2) حتى يتوفر مزود.
- الأسلوب المقترح: OTP يولده ويتحقق منه خادمنا (مجزّأ، صلاحية، عداد) والمزود قناة إرسال فقط، فلا نعتمد على OTP المدمج المرتبط بهاتف مستخدم Auth.

## D. عقد البيانات وواجهات API المقترح

| العملية | الطرف | المدخلات | المخرجات |
|---|---|---|---|
| إنشاء ولي | إدارة (RPC) | الاسم، الهاتف، المدرسة | `guardian_id`, `account_code` |
| ربط/فك ربط ابن | إدارة | `guardian_id, student_id, relation, permissions` | رابط بحالة `verified` + سجل تدقيق |
| إصدار رمز تفعيل | إدارة | `guardian_id` | رمز يُعرض مرة واحدة |
| التفعيل | Android → `/api/public/parent-auth/activate` | `account_code, activation_code, password` | رد موحد ثم جلسة |
| الدخول | Android → Auth | `account_code` (يتحول لبريد داخلي) + كلمة المرور | access/refresh tokens |
| طلب OTP | Android → `/api/public/parent-auth/otp/request` | `account_code` | دائماً "إن كان الحساب موجوداً سيصلك رمز" |
| تحقق + كلمة جديدة | Android → `/otp/verify` | `account_code, otp, new_password` | رد موحد؛ إلغاء كل الجلسات القديمة |
| عرض الأبناء | Android → RPC `parent_children()` | جلسة فقط | الأبناء المرتبطون الموثقون فقط |
| تبديل الابن | Android محلياً + كل RPC تقبل `student_id` وتتحقق من الرابط في SQL | `student_id` | بيانات الابن أو خطأ عام |
| إيقاف/إلغاء | إدارة | `guardian_id, reason` | حالة جديدة + إلغاء الجلسات + سجل |

كل الردود العامة لا تذكر الاسم أو الأبناء أو وجود الحساب، ورسالة الخطأ ثابتة، وزمن الرد متقارب.

## E. تصميم قاعدة البيانات (تصميم فقط)

- **إعادة استخدام:** `guardians`, `guardian_students`, `guardian_activation_codes`, `parent_check_activation`, نمط البريد الاصطناعي، `audit_trigger`.
- **إضافة:**
  - `guardians`: `phone_verified_at`, `status_changed_at/by`؛ فك قيد المدرسة الواحدة (جعل `school_id` اختيارياً أو جدول `guardian_schools`) — يحتاج قراركم.
  - `guardian_students`: `link_status` (pending/verified/revoked)، `verified_at`, `revoked_at/by/reason`؛ استبدال الحذف المتتالي بـ RESTRICT.
  - `guardian_otp_codes`: رمز مجزّأ، الغرض، صلاحية قصيرة، محاولات، `consumed_at` — مغلق إلا لـ service_role.
  - `guardian_auth_attempts`: للتقييد الدائم حسب IP والمعرّف.
  - دوال قراءة للولي (`parent_children`, `parent_attendance(student)`, …) بـ SECURITY DEFINER وsearch_path ثابت، تشترط: ولي مفعّل ← رابط موثق ← بيانات منشورة.
  - audit triggers على كل الجداول الجديدة وعلى guardians/guardian_students.
- **تجنّب:** تشغيل 0011 أو 0010 على الإنتاج؛ أي PIN نصي؛ قراءة الولي للجداول الأساسية مباشرة؛ الهاتف كمعرّف دخول؛ OTP المدمج المرتبط بهاتف Auth قبل قرار المزود.

## G. اختبارات القبول الإلزامية

- أسرتان: ولي A لا يقرأ ابن B حتى بتعديل الطلب مباشرة.
- ولي بعدة أبناء في مدارس مختلفة يرى جميعهم فقط.
- طالب له وليّان: كل واحد يرى حسب صلاحياته؛ فك ربط أحدهما لا يؤثر على الآخر.
- OTP منتهي، مستخدم سابقاً، تجاوز المحاولات → رفض بنفس الرسالة.
- منع التعداد: رقم موجود/غير موجود/موقوف → نفس الرد ونفس رمز الحالة وزمن متقارب.
- تقييد المعدل يصمد عبر إعادة تشغيل الخادم.
- الإيقاف يبطل الجلسات القائمة فوراً.
- إعادة التعيين تبطل كل الجلسات القديمة.
- لا توجد كلمة مرور أو رمز نصي في أي جدول أو سجل.
- انقطاع الشبكة: التطبيق يعرض آخر بيانات محفوظة مشفرة مع تنبيه، ولا يكرر عمليات عند العودة.
- كل تفعيل/ربط/إيقاف/إعادة تعيين يظهر في سجل التدقيق.
